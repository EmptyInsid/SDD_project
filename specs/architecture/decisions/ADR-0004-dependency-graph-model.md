# ADR-0004: Ориентированный граф зависимостей как ядро модели

- **Статус:** принято
- **Дата:** 2026-11-04

## Контекст

Нужна формальная модель для контроля согласованности и Change Impact Analysis.

## Решение

Использовать типизированный ориентированный граф $G=(V,E)$ с типами вершин (`code`, `req`, `arch`, `test`, `ext`) и рёбер (`dep`, `sat`, `con`, `test`). Архитектурные ограничения — разрешённое отношение $A \subseteq L \times L$; нарушение — ребро с парой слоёв вне $A$.

## Обоснование

- Единая модель связывает требования, компоненты, код и тесты.
- Транзитивное замыкание по обратным рёбрам даёт Change Impact Analysis.
- Проверка ограничений сводится к проверке принадлежности разрешённому отношению.

## Последствия

- Плюсы: унификация алгоритмов, воспроизводимость.
- Минусы: необходимость точного сопоставления кода со слоями (`layer(v)`), задаётся архитектором.
- Детали — `docs/project-report.md`, Раздел 4.
