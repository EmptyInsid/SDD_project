# ADR-0002: Модульный монолит + гексагональная архитектура

- **Статус:** принято
- **Дата:** 2026-11-04

## Контекст

Выбор укрупнённой архитектуры. Рассмотрены: клиент-сервер, модульный монолит, гексагональная, микросервисы.

## Решение

Использовать модульный монолит с гексагональной организацией ядра (домен + порты + адаптеры). Микросервисы на MVP не применять.

## Обоснование

- Один процесс упрощает развёртывание и отладку для одного разработчика.
- Порты/адаптеры дают инверсию зависимостей и лёгкую замену Git/БД/LLM.
- Возможность позднее выделить модули в сервисы без изменения домена.

## Последствия

- Плюсы: простота, тестируемость, расширяемость.
- Минусы: потенциальные ограничения масштабирования (приемлемо для MVP).
- Требование: жёсткие границы модулей, запрет импортов через границы в обход портов.
