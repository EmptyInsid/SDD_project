# Архитектурное описание ACIA

> Укрупнённая архитектура системы. Согласована с `docs/project-report.md` (Раздел 7) и `docs/technology-stack.md`.

## 1. Архитектурный стиль

- **Модульный монолит** — основной стиль для MVP: один процесс, изолированные модули.
- **Гексагональная архитектура** — внутренняя организация ядра (домен + порты + адаптеры).
- **Клиент-серверная модель доступа** — CLI/API как клиент к ядру.

Микросервисы **не применяются** на этапе MVP (см. ADR-0002).

## 2. Модули и ответственность

| Модуль | Ответственность | Ключевые порты |
|---|---|---|
| `interfaces` | CLI/HTTP вход, вывод отчётов, exit-коды | — |
| `spec` | Спецификации: требования, ограничения, ADR | `SpecStore` |
| `analysis` | AST-анализ Go, извлечение зависимостей | `SourceReader` |
| `graph` | Модель графа, замыкание, циклы | `GraphStore` |
| `conformance` | Сопоставление и поиск отклонений | `SpecReader` |
| `impact` | Change Impact Analysis, классификация | `DiffReader` |
| `docgen` | Диаграммы и черновики документации | `DocumentRenderer` |
| `llm` | Опциональная интерпретация | `LLMClient` |
| `git` | Чтение репозитория, diff, история | `SourceReader`, `DiffReader` |
| `repo` | Персистентность (PostgreSQL/файлы) | `GraphStore`, `SpecStore` |

## 3. Поток данных

1. `interfaces` → команда.
2. `analysis` (через `git`) → элементы кода → `graph`.
3. `conformance` ← граф + `spec` → отклонения.
4. `impact` ← diff + граф → затронутые элементы.
5. `docgen` (+ опционально `llm`) → отчёты/диаграммы.
6. `repo` сохраняет результаты; `interfaces` возвращает их.

## 4. Внутренние и внешние интерфейсы

- **Внутренние (порты):** `SourceReader`, `DiffReader`, `GraphStore`, `SpecStore`, `LLMClient`, `DocumentRenderer`.
- **Внешние:** Git (чтение), PostgreSQL (хранение), LLM-провайдер (HTTP), файловая система, CI/CD (exit-коды/JSON).

## 5. Взаимодействие с LLM и Git

- **LLM:** изолированный адаптер; только интерпретация; результат — предложение, требующее подтверждения.
- **Git:** только чтение; ACIA не выполняет push и автоматические коммиты.

## 6. Хранение данных

- Основная СУБД — PostgreSQL (см. ADR-0003).
- Для офлайн MVP допустимо файловое хранилище/SQLite; переход не требует изменения домена (за портом `GraphStore`/`SpecStore`).

## 7. Расширяемость

- Новый язык → новый адаптер `SourceReader`.
- Новый LLM-провайдер → новый адаптер `LLMClient`.
- Изменение правил → изменение данных спецификации, а не кода ядра.
